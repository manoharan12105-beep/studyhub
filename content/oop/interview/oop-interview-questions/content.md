# OOP Interview Questions by Level

## Definition

A graded question bank for Java OOP interviews, from the first technical round of a campus placement to experienced-level backend interviews. Questions are grouped **Beginner → Intermediate → Advanced**, and each answer is written the way a strong candidate would *say* it: the direct answer first, then the reason, then a short example.

## Why It Matters

- OOP questions appear in almost every Java interview: written tests, technical rounds, and as follow-ups to coding problems ("why did you make this class immutable?").
- Interviewers move from definitions to reasoning quickly. Knowing the *why* behind each rule is what distinguishes a prepared answer from a memorised one.

## How the Questions Are Labelled

Each question carries a **Style** line describing the kind of interview where that style of question is commonly useful. These labels are **guidance for preparation, not claims about any specific company**:

| Label | Meaning |
|-------|---------|
| **Placement-style** | Definition and comparison questions typical of campus placement drives and first technical rounds |
| **Service-company-style** | Fundamentals plus Java rules, commonly useful for IT-services hiring |
| **Java interview** | Java-language-specific behaviour and rules |
| **Backend interview** | Design-oriented questions relevant to Spring Boot / backend roles |
| **Product-company-style** | Deeper reasoning, trade-offs and design judgement |
| **Frequently useful** | Comes up across many kinds of interviews |
| **Advanced interview** | Experienced-level depth |

StudyHub does not have verified lists of questions asked by particular companies, and none are implied.

## How to Answer OOP Questions

1. **Lead with a one-sentence definition.** "Polymorphism means one interface, many implementations — chosen at runtime by the object's actual type."
2. **Give the Java mechanism.** "In Java that is method overriding plus dynamic dispatch."
3. **Show a tiny example.** `Shape s = new Circle(); s.area();`
4. **Add the why or the trade-off.** "It lets new shapes be added without changing the code that uses them."
5. **Stop.** Let the interviewer ask follow-ups.

## Key Takeaways

- Rehearse aloud: definition → Java mechanism → example → why.
- Beginner questions test vocabulary; intermediate test Java rules and comparisons; advanced test reasoning and design.
- Style labels guide preparation; they are not company-specific claims.
