# Memory Management Fundamentals

**Module:** Memory Management · **Interview priority:** Core

## Concept

**Memory management** is how the OS shares main memory (RAM) among processes: it decides where each process lives, keeps processes from touching each other's memory, and reclaims memory when they finish.

The central idea is the split between two kinds of address:

- **Logical address** (virtual address) — the address the CPU generates while running a program. Every process sees its own addresses starting from 0.
- **Physical address** — the real location in RAM, seen by the memory hardware.

The **Memory Management Unit (MMU)**, a hardware component, translates every logical address into a physical one at run time.

## Why It Matters

Many processes must be in memory at once for multiprogramming. Without translation and protection, every program would have to know where it will be loaded, and a bug in one could overwrite another — or the kernel. Paging, segmentation and virtual memory (the rest of this module) are all refinements of this one mechanism.

## How It Works

### Address binding

When are a program's addresses turned into real addresses?

| Time | How | Consequence |
|------|-----|-------------|
| Compile time | Compiler emits absolute addresses | Program must always load at the same place (MS-DOS .COM files) |
| Load time | Loader adds the load address to relocatable code | Fixed after loading; cannot move |
| **Execution time** | MMU translates on every access | Process can be moved in memory while running — what modern OSes use |

### Base and limit registers (simplest MMU)

Each process gets one contiguous block of memory. Two registers, loaded at each context switch:

- **Base** (relocation) register — where the block starts in physical memory.
- **Limit** register — how large it is.

```text
 logical address L
      │
      ▼
   L < limit ? ──no──▶ trap: addressing error (segmentation fault)
      │ yes
      ▼
 physical = base + L
```

Example: base = 40000, limit = 12000. Logical 3500 → 3500 < 12000 → physical **43500**. Logical 12500 → ≥ limit → **trap**.

### Contiguous allocation and the hole-fitting strategies

With **variable partitions**, memory is a mix of allocated blocks and free **holes**. A new process needs one hole large enough:

- **First fit** — the first hole that is big enough. Fast.
- **Best fit** — the smallest hole that is big enough. Leaves the smallest leftover; must search all holes.
- **Worst fit** — the largest hole. Leaves a large leftover; usually performs worst.

### Fragmentation

- **External fragmentation** — enough total free memory exists, but it is split into holes too small to use. Caused by variable-size allocation. Cure: **compaction** (move processes together; needs execution-time binding) or non-contiguous allocation (**paging**).
- **Internal fragmentation** — memory allocated to a process but unused inside its block, because blocks come in fixed sizes. Example: a 1 MB fixed partition holding a 900 KB process wastes 100 KB.

### Swapping

A process can be moved temporarily from memory to disk (**swapped out**) and brought back later (**swapped in**), letting the total memory of all processes exceed RAM. Modern systems swap individual **pages** rather than whole processes — see [Virtual Memory](../virtual-memory/content.md).

## Example

Free holes in memory order: **150, 400, 250, 300, 100 KB**. Processes arrive in order: **230, 120, 280, 90 KB**.

| Process | First fit | Best fit | Worst fit |
|---------|-----------|----------|-----------|
| 230 | 400 → 170 left | 250 → 20 left | 400 → 170 left |
| 120 | 150 → 30 left | 150 → 30 left | 300 → 180 left |
| 280 | 300 → 20 left | 300 → 20 left | **must wait** (largest hole is 180) |
| 90 | 170 → 80 left | 100 → 10 left | 250 → 160 left |

Best fit and first fit place all four; worst fit splits the big holes early and cannot place the 280 KB process even though 810 KB is free in total — **external fragmentation** in action.

## Comparison

| Aspect | Logical address | Physical address |
|--------|-----------------|------------------|
| Generated by | CPU (the running program) | MMU, after translation |
| Seen by | The process | Memory hardware |
| Range | 0 … size of the process's address space | 0 … size of RAM |
| Same value means same location? | No — each process has its own | Yes |
| Also called | Virtual address | Real address |

## Important Points

- The CPU generates logical addresses; the MMU translates them to physical addresses at run time.
- Base + limit: physical = base + logical, if logical < limit; otherwise trap.
- Hole selection: first fit (fast), best fit (smallest leftover), worst fit (largest leftover).
- External fragmentation: free memory scattered in small holes → compaction or paging.
- Internal fragmentation: unused space inside an allocated block → fixed-size units.

## Common Confusion

> [!WARNING]
> **Internal vs external fragmentation.** *Internal* = wasted **inside** an allocated unit (fixed sizes, paging's last page). *External* = wasted **between** allocated units (variable sizes, segmentation, contiguous allocation).

- **"Best fit is always best."** It leaves many tiny, useless holes; first fit is usually as good and faster.
- **Logical address ≠ "fake" address.** It is real for the process; it is just translated before it reaches RAM.

## Quick Revision

- Logical (CPU) → MMU → physical (RAM). Execution-time binding.
- Base/limit: check L < limit, then base + L.
- First fit · best fit · worst fit.
- External fragmentation (between blocks) → compaction/paging; internal (inside blocks) → smaller units.
