# Memory Management Fundamentals — Interview Questions

## Beginner

### Q1. What is the difference between a logical and a physical address?

**Style:** Comparison

<details>
<summary>Answer</summary>

A logical (virtual) address is generated by the CPU while a program runs; each process has its own logical address space starting at 0. A physical address is an actual location in RAM. The MMU translates logical addresses to physical addresses at run time, so the same logical address in two processes maps to different physical locations.

</details>

### Q2. What is the MMU?

**Style:** Direct

<details>
<summary>Answer</summary>

The Memory Management Unit is the hardware that translates every logical address issued by the CPU into a physical address and checks that the access is allowed. In the simplest form it adds a base (relocation) register after checking a limit register; in paging systems it uses page tables and a TLB.

</details>

### Q3. What is the difference between internal and external fragmentation?

**Style:** Comparison

<details>
<summary>Answer</summary>

**Internal fragmentation** is unused memory inside an allocated block, because allocation happens in fixed-size units larger than the request (a 4 KB page holding 1 KB of data). **External fragmentation** is free memory split into many small non-contiguous holes, so a request cannot be satisfied even though the total free memory is enough. Paging eliminates external fragmentation but has internal fragmentation in the last page.

</details>

## Intermediate

### Q4. How do base and limit registers protect memory?

**Style:** How

<details>
<summary>Answer</summary>

The OS loads the running process's base and limit into the MMU at each context switch (privileged instructions). For every access the hardware checks logical address < limit; if not, it traps to the OS (addressing error). Otherwise physical = base + logical. A process therefore cannot reach memory outside its own block, and only the kernel can change the registers.

</details>

### Q5. Compare first fit, best fit and worst fit.

**Style:** Comparison

<details>
<summary>Answer</summary>

**First fit** takes the first hole large enough — fastest, generally good. **Best fit** takes the smallest hole large enough — smallest leftover, but must search the whole list and leaves tiny unusable holes. **Worst fit** takes the largest hole — leaves a big leftover that may be reusable, but it breaks up large holes early and usually performs worst. Simulations show first and best fit beat worst fit in utilisation; first fit is faster.

</details>

### Q6. How can external fragmentation be reduced?

**Style:** How

<details>
<summary>Answer</summary>

**Compaction**: move allocated blocks together so the free memory forms one large hole — possible only with execution-time address binding, and expensive. Or allow **non-contiguous allocation**: paging (fixed-size frames anywhere in memory) removes external fragmentation entirely; segmentation with paging combines both.

</details>

### Q7. What are the three times at which address binding can happen?

**Style:** Direct

<details>
<summary>Answer</summary>

**Compile time** — absolute code; the program must always load at the same address. **Load time** — relocatable code is adjusted when loaded; it cannot move afterwards. **Execution time** — addresses are translated by the MMU on every access, so the process can be moved or partly swapped while running. Modern OSes use execution-time binding.

</details>

## Advanced

### Q8. Base = 40000, limit = 12000. What physical addresses do logical addresses 3500 and 12500 map to?

**Style:** Calculation

<details>
<summary>Answer</summary>

3500 < 12000 → physical **43500**. 12500 ≥ 12000 → **trap** (addressing error); no physical address is produced. Note the comparison uses the logical address against the limit, before the base is added.

</details>

### Q9. What is swapping, and how is it different from paging to disk?

**Style:** Comparison

<details>
<summary>Answer</summary>

Classic swapping moves an **entire process** between memory and a backing store, so the transfer time is proportional to the whole process size. Modern systems page instead: they move **individual pages** in and out on demand, so only the parts actually needed are in RAM. "Swap space" on Linux is the disk area used for those paged-out pages.

</details>
