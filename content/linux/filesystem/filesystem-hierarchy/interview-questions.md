# The Linux Filesystem Hierarchy — Interview Questions

## Beginner

### Q1. What is the root directory, and how is it different from `/root`?

<details>
<summary>Answer</summary>

`/` is the root of the entire directory tree — every absolute path starts there. `/root` is the home directory of the root user. They are unrelated apart from the name.

</details>

### Q2. What is stored in `/etc`?

<details>
<summary>Answer</summary>

System-wide configuration, almost always as text files: accounts (`/etc/passwd`, `/etc/group`, `/etc/shadow`), networking (`/etc/hosts`, `/etc/resolv.conf`), mounts (`/etc/fstab`), scheduled jobs (`/etc/crontab`), and service configuration (`/etc/ssh/sshd_config`, `/etc/nginx/`). No binaries.

</details>

### Q3. What is `/var` used for?

<details>
<summary>Answer</summary>

Variable data that grows and changes while the system runs: logs (`/var/log`), application state such as databases and Docker data (`/var/lib`), caches (`/var/cache`), queues (`/var/spool`) and temporary files that survive reboot (`/var/tmp`). It is the usual suspect when a disk fills up.

</details>

### Q4. What is the difference between `/bin` and `/sbin`?

<details>
<summary>Answer</summary>

`/bin` holds commands for all users (`ls`, `cp`, `cat`); `/sbin` holds system administration commands mostly run by root (`fdisk`, `mkfs`, `ip`, `reboot`). On modern distributions both are symbolic links into `/usr/bin` and `/usr/sbin` ("merged /usr").

</details>

### Q5. What is in `/home`?

<details>
<summary>Answer</summary>

One directory per normal user, e.g. `/home/student`, holding that user's files and personal configuration (dotfiles such as `.bashrc`, `.ssh/`). `~` in the shell expands to your home directory.

</details>

### Q6. What are `/proc` and `/sys`?

<details>
<summary>Answer</summary>

Virtual filesystems generated by the kernel on demand. `/proc` has a directory per process (`/proc/<pid>/cmdline`, `status`, `fd/`) and system information (`/proc/cpuinfo`, `/proc/meminfo`, `/proc/loadavg`). `/sys` exposes devices, drivers and kernel settings in a structured tree. They use no disk space.

</details>

## Intermediate

### Q7. What is the difference between `/opt` and `/usr/local`?

<details>
<summary>Answer</summary>

Both are for software not installed by the distribution's package manager. `/opt/<package>` keeps a self-contained application in its own directory (vendor bundles such as `/opt/jdk-21`). `/usr/local` mirrors `/usr` (`/usr/local/bin`, `/usr/local/lib`) and suits software you compile and install yourself; `/usr/local/bin` is normally on `PATH` ahead of `/usr/bin`.

</details>

### Q8. What is the difference between `/tmp` and `/var/tmp`?

<details>
<summary>Answer</summary>

`/tmp` is for short-lived temporary files; many systems clear it at boot or mount it as tmpfs in RAM. `/var/tmp` is for temporary files that should survive a reboot. Both are world-writable with the sticky bit so users cannot delete each other's files.

</details>

### Q9. What are `/dev/null`, `/dev/zero` and `/dev/random`?

<details>
<summary>Answer</summary>

Character device files. `/dev/null` discards everything written to it and returns end-of-file when read — used to silence output (`2>/dev/null`). `/dev/zero` returns an endless stream of zero bytes (used to create files of a given size). `/dev/random` and `/dev/urandom` return cryptographically secure random bytes.

</details>

### Q10. How do you tell the file type from `ls -l` output?

<details>
<summary>Answer</summary>

The first character: `-` regular file, `d` directory, `l` symbolic link, `c` character device, `b` block device, `p` named pipe, `s` socket. `file <name>` also describes contents (text, ELF executable, gzip data).

</details>

## Advanced

### Q11. Why were `/bin` and `/usr/bin` historically separate, and why merge them?

<details>
<summary>Answer</summary>

Early Unix systems kept `/usr` on a separate disk, so `/bin`, `/sbin` and `/lib` held what was needed to boot and repair the system before `/usr` was mounted. Today the initramfs handles early boot, and keeping the split caused bugs (tools in `/usr/bin` needed early, duplicate paths). Merging makes `/bin` etc. symlinks into `/usr`, so the OS can be treated as one read-only `/usr` tree.

</details>

### Q12. A process's binary was deleted, but the process is still running. Can you recover the binary?

<details>
<summary>Answer</summary>

Yes, while the process runs: `/proc/<pid>/exe` is a link to the executable the kernel still holds open, so `cp /proc/<pid>/exe /tmp/recovered` copies it. The same idea works for deleted files a process still has open, via `/proc/<pid>/fd/<n>`. This is also how you find "deleted but open" files that keep disk space in use.

</details>
