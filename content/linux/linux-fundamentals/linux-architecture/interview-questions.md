# Linux Architecture — Interview Questions

## Beginner

### Q1. Describe the layers of the Linux architecture.

<details>
<summary>Answer</summary>

From bottom to top: **hardware**; the **kernel** (scheduler, memory manager, filesystems, network stack, drivers, security) running in privileged mode; the **system call interface**; **libraries** such as glibc; and **user space** — the shell, utilities and applications. User programs reach hardware only through system calls.

</details>

### Q2. What is the difference between user space and kernel space?

<details>
<summary>Answer</summary>

Kernel space is where the kernel runs with full hardware privileges and access to all memory. User space is where ordinary programs run, restricted by the CPU: each process has its own virtual memory and cannot access devices or other processes directly. A bug in user space crashes one process; a bug in kernel space can crash the system (kernel panic).

</details>

### Q3. What is a system call? Give examples.

<details>
<summary>Answer</summary>

A system call is a controlled request from a user program to the kernel for a privileged service. Examples: `open`/`openat`, `read`, `write`, `close` (files), `fork`, `execve`, `exit`, `wait` (processes), `kill` (signals), `socket`, `connect` (networking). Programs usually invoke them through the C library.

</details>

### Q4. What is PID 1?

<details>
<summary>Answer</summary>

The first user-space process the kernel starts at boot — the **init** system, which is systemd on most modern distributions. It starts and supervises services, and it adopts orphaned processes (and reaps them when they exit). If PID 1 dies, the kernel panics.

</details>

### Q5. What does "everything is a file" mean in Linux?

<details>
<summary>Answer</summary>

Many resources are accessed through the same file interface (open, read, write, close): regular files, directories, devices (`/dev/sda`, `/dev/null`, `/dev/tty`), kernel information (`/proc`, `/sys`), and — as file descriptors — pipes and sockets. The same tools and redirection therefore work on all of them.

</details>

## Intermediate

### Q6. What happens when you type `ls -l` in a shell and press Enter?

<details>
<summary>Answer</summary>

Bash reads and parses the line, performs expansions, and resolves `ls`: alias? function? builtin? Otherwise it searches `$PATH` and finds `/usr/bin/ls`. It calls `fork()` to create a child; the child calls `execve()` to load `ls` with arguments `["ls", "-l"]`. `ls` uses system calls to read the directory and file metadata (the kernel checks permissions) and writes the result to file descriptor 1 (the terminal). When `ls` exits, bash's `wait()` returns, the exit status goes into `$?`, and the prompt is printed again.

</details>

### Q7. Is Linux a monolithic kernel or a microkernel?

<details>
<summary>Answer</summary>

Monolithic: core services and drivers run together in kernel space, which is fast. It is also modular — drivers and filesystems can be loaded and unloaded at runtime as kernel modules (`lsmod`, `modprobe`). A microkernel keeps only minimal functions in the kernel and runs drivers as user-space servers.

</details>

### Q8. Describe the Linux boot process.

<details>
<summary>Answer</summary>

UEFI/BIOS firmware initialises hardware and starts the boot loader (GRUB). GRUB loads the kernel and the initramfs. The kernel initialises CPUs, memory and drivers, uses the initramfs to reach and mount the real root filesystem, then starts init (systemd) as PID 1. systemd brings up services by dependency (targets), and finally a login prompt, SSH or display manager accepts users.

</details>

### Q9. Are the files in `/proc` stored on disk?

<details>
<summary>Answer</summary>

No. `/proc` (procfs) and `/sys` (sysfs) are virtual filesystems. Their contents are generated by the kernel when read — process details in `/proc/<pid>/`, memory in `/proc/meminfo`, CPU in `/proc/cpuinfo`. Most show size 0 and use no disk space.

</details>

## Advanced

### Q10. What is the difference between `fork()` and `exec()`?

<details>
<summary>Answer</summary>

`fork()` creates a new process that is a copy of the caller (same code, memory copied lazily with copy-on-write, new PID). `exec()` (`execve`) replaces the program running in the current process with a new one, keeping the PID and open file descriptors. A shell runs an external command with fork then exec, which lets it set up redirections in the child between the two calls.

</details>

### Q11. A program fails with "No such file or directory" but does not say which file. How would you find out?

<details>
<summary>Answer</summary>

Trace its system calls: `strace -f -e trace=openat,stat,execve ./program 2>&1 | grep ENOENT`. The failing call shows the exact path. Other options: check the program's verbose/debug flag, or `ltrace` for library calls. For a binary that will not start at all, `ldd ./program` shows missing shared libraries.

</details>

### Q12. What is a kernel panic and how is it different from an application crash?

<details>
<summary>Answer</summary>

A kernel panic is a fatal error inside the kernel (for example a driver bug, corrupt memory, or PID 1 exiting) from which it cannot safely recover, so the whole system halts or reboots. An application crash (segmentation fault, uncaught exception) only terminates that process; the kernel cleans up its resources and everything else keeps running.

</details>
